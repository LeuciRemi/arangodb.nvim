INTRODUCTION                                              *arangodb.nvim-intro*

arangodb.nvim provides a picker-based interface for ArangoDB. It can:

- browse databases, collections, and cursor-paginated documents asynchronously
- search sampled document fields, sort collection views, and reopen a view in
  AQL
- edit, validate, explain, execute, and profile AQL queries
- complete AQL keywords, built-in functions, and collection names; mark server
  syntax errors as diagnostics
- edit JSON documents, save with |:write|, and resolve revision conflicts
- create and duplicate draft documents
- create, duplicate, rename, truncate, and drop collections asynchronously
- edit collection properties and schemas, and manage indexes
- duplicate supported collection properties and secondary indexes
- infer direct, nested, and reverse document relations
- persist named AQL queries, attach real .aql files, and export the displayed
  page or every cursor page
- explore bounded neighborhoods in named graphs
- resolve passwords lazily from functions, environment variables, or commands
- connect through HTTP or HTTPS

The interface uses snacks.nvim. HTTP uses a built-in libuv transport, while
HTTPS uses curl.

===============================================================================
REQUIREMENTS                                      *arangodb.nvim-requirements*

- Neovim >= 0.10
- folke/snacks.nvim with its picker enabled (v2.31.0 is tested in CI)
- curl for https:// connections
- an ArangoDB server reachable through its HTTP API (3.12 is tested)

INSTALLATION                                      *arangodb.nvim-installation*

Example for lazy.nvim:

>lua
  {
    "LeuciRemi/arangodb.nvim",
    dependencies = {
      { "folke/snacks.nvim", opts = { picker = { enabled = true } } },
    },
    opts = {
      connections = {
        local_db = "http://root:password@127.0.0.1:8529/my_database",
      },
      default_database = "local_db",
    },
  }
<

===============================================================================
QUICK START                                         *arangodb.nvim-quickstart*

The installation example uses local_db as a connection alias and my_database
as the actual database name in its URL. Replace the dummy URL with your server
and an existing database, then:

1. Run :checkhealth arangodb for local dependency and configuration checks.
2. Run :ArangoBrowse local_db and select a collection, then a document.
3. Edit its JSON and :write to save it to the database.
4. Use <C-x> in a picker for actions and :ArangoResume to resume browsing.
5. Run :ArangoAql local_db for an AQL editor.

The health check does not verify collection access or authentication. For a
real disposable server with fictional data and the README GIF recorder, see
https://github.com/LeuciRemi/arangodb.nvim/blob/main/demo/README.md.

                                                        *arangodb.nvim-options*

connections ~
    Named connection URLs or structured profiles. Profiles accept url, user or
    username, and one of password, password_env, or password_command. Password
    callbacks and commands are evaluated only when the connection is opened.
    password_command_timeout defaults to 10000 milliseconds.

default_database ~
    Preferred connection name. May also be a { name, url } table.

auto_discover ~
    Query /_api/database/user using the NVIM_ARANGO_HOST settings. Disabled by
    default to prevent implicit network requests during completion and health
    checks.

keymaps ~
    Optional global normal-mode mappings for browse, resume, and back. They are
    unset by default.

picker_keymaps ~
    Picker-local mappings. Navigation and the actions menu work in normal and
    insert mode. Write mappings are unset by default and, when configured, are
    normal-mode-only. Any value may be false to disable that mapping.
    drop_collection adds a key for dropping the selected collection; sort and
    open_aql add keys for the document picker's sort and AQL actions. All
    three are unset by default, while the actions stay in the <C-x> menu.

document_keymaps ~
    Buffer-local mappings for save, delete, duplicate, related, and graph. They
    are unset by default. The corresponding commands are always created.

graph_keymaps ~
    Graph-buffer mappings for opening a vertex, changing the start vertex,
    refreshing, changing depth, and cycling direction. Any value may be false.

aql_keymaps ~
    Buffer-local AQL editor and result mappings. Any value may be false. No
    global AQL mapping is installed.

aql ~
    AQL editor settings. batch_size controls cursor pages, cursor_ttl is in
    seconds, and max_runtime is a duration in seconds (nil uses the server
    default). result_split is
    auto, right, or bottom. result_format is json or table. history configures
    private local history and library.path configures named-query storage.

graph ~
    Named-graph traversal defaults. depth is capped at 10 by the explorer,
    max_nodes bounds a result, and direction is ANY, OUTBOUND, or INBOUND.

layout ~
    snacks.nvim picker layout. preset = "auto" uses a side-by-side layout on
    wide screens and a stacked layout on smaller screens. preview controls the
    preview window.

field_sample_size ~
    Documents sampled when discovering filter and reverse-relation fields.

page_size ~
    Documents requested per ArangoDB cursor page.

json_indent ~
    Spaces used to format JSON buffers and previews.

truncate_length ~
    Maximum displayed field length in picker rows.

max_field_depth ~
    Maximum recursion depth for nested field discovery.

aql_batch_size ~
    Batch size for other client AQL operations. This differs from page_size
    (browser pages) and aql.batch_size (AQL editor result pages).

cache_ttl ~
    Lifetime in milliseconds for cached collection metadata, sampled fields,
    and figures. Set to 0 to disable caching. Collection previews load
    per-collection figures and database-wide document and approximate-size
    totals in the background.

default_sort ~
    AQL sort expression used by document and relation listings.

show_system_collections ~
    Include system collections in the collection picker.

http_timeout ~
    HTTP request timeout in milliseconds.

tls_verify ~
    Verify HTTPS certificates. Disabling this is not recommended.

tls_ca_file ~
    Optional CA bundle passed to curl with --cacert.

diagnostics ~
    Optional sanitized JSON-lines request journal. enabled activates it; path
    overrides stdpath("log")/arangodb.nvim.log. max_size is the rotation
    threshold in bytes (default 1048576); the previous file is kept as .1.
    Credentials, headers, and request bodies are never written.

===============================================================================
CONNECTIONS                                          *arangodb.nvim-connections*

Connection URLs have this form:

  http[s]://[user:password@]host[:port]/database

A URL that cannot be parsed, for example one without http:// or https://, is
rejected by setup() with an error that names the connection. It is never used
for a request.

Connections come from setup().connections, then vim.g.arangodb_connections,
then NVIM_ARANGO_<NAME>_URL. The first source wins for duplicate names. Enabled
auto-discovery adds only names not already configured.

Authentication is optional. Credentials may be percent-encoded. IPv6 hosts
must use brackets, for example:

>lua
  connections = {
    no_auth = "http://127.0.0.1:8529/example",
    encoded = "https://user%40example.com:p%40ssword@db.example.com:8529/example",
    ipv6 = "http://[::1]:8529/example",
  }
<

Structured profiles keep secrets out of URLs:

>lua
  connections = {
    work = {
      url = "https://db.example.com:8529/work",
      username = "reader",
      password_env = "ARANGODB_WORK_PASSWORD",
    },
    vault = {
      url = "https://db.example.com:8529/vault",
      username = "reader",
      password_command = { "security", "find-generic-password", "-w",
                           "-s", "arangodb-vault" },
    },
    dynamic = {
      url = "http://127.0.0.1:8529/example",
      username = "reader",
      password = function(context) return load_secret(context.name) end,
    },
  }
<

load_secret represents a user-provided function, not a plugin API. The
security command is specific to the macOS Keychain.

password_command may also be a shell command string. It must print only the
password to standard output. It defaults to a 10-second timeout, configurable
with password_command_timeout. Resolved secrets are not shown in completion or
health output.

Avoid storing credentials in version-controlled configuration. Every
NVIM_ARANGO_<NAME>_URL environment variable is detected automatically. The
database name is read from the URL.

Server-wide discovery uses these variables when auto_discover is true. They
also build a connection when :ArangoBrowse receives an unconfigured name:

- NVIM_ARANGO_HOST (default 127.0.0.1)
- NVIM_ARANGO_PORT (default 8529)
- NVIM_ARANGO_SCHEME (http, https, ssl, or tls)
- NVIM_ARANGO_USER (default root)
- NVIM_ARANGO_PASSWORD (default root)
- NVIM_ARANGO_SYSTEM_URL

COMMANDS                                              *arangodb.nvim-commands*

Commands that accept a [database] argument complete from configured connection
names and from database names discovered earlier in the session. Completion
performs no network requests.

                                                        *:ArangoBrowse*
:ArangoBrowse [database]
    Open the database and collection browser. A database argument skips the
    database picker.

                                                        *:ArangoResume*
:ArangoResume
    Re-show the active picker, or reopen the last collections or collection
    view when the picker was closed. Fall back to |:ArangoBrowse| when no view
    has been opened yet.

                                                         *:ArangoBack*
:ArangoBack
    Return to the previous picker or document route. A document that cannot
    be reopened leaves its history entry in place.

                                                          *:ArangoAql*
:ArangoAql [database]
    Open a new AQL editor. A database argument skips database selection.

                                                   *:ArangoAqlAttach*
:ArangoAqlAttach [database]
    Attach AQL commands and the bind-variable companion to the current .aql
    file without converting it to a scratch buffer.

                                                  *:ArangoAqlLibrary*
:ArangoAqlLibrary [database]
    Open an AQL editor and immediately browse named queries for the database.

                                                        *:ArangoGraph*
:ArangoGraph [database]
    Select a named graph and explore a bounded neighborhood.

                                                *:ArangoDocumentSave*
:ArangoDocumentSave
    Save the current document. A draft is inserted on its first save. |:write|
    performs the same action in an ArangoDB document buffer. Existing
    documents use _rev to detect concurrent changes and offer reload, compare,
    or explicit force-overwrite actions on conflict.

                                            *:ArangoDocumentDuplicate*
:ArangoDocumentDuplicate
    Open a copy of the current document as a draft with a fresh key.

                                              *:ArangoDocumentDelete*
:ArangoDocumentDelete
    Delete the current document after confirmation, or discard a draft.
    Edits made while deletion or collection truncation is in progress are
    retained in a detached recovery buffer. Saving to the deleted document is
    blocked; use :write <file> for a local copy or :ArangoDocumentDuplicate to
    recover the content as a new draft.

                                             *:ArangoDocumentRelated*
:ArangoDocumentRelated
    Pick a direct, nested, or inferred reverse relation from the document.

                                         *:ArangoDocumentGraph*
:ArangoDocumentGraph
    Select a named graph and use the current document as its start vertex.

AQL EDITOR                                                *arangodb.nvim-aql*

Every |:ArangoAql| call creates a separate, listed query buffer with the aql
filetype. If the current tab page already contains an AQL session, the next
session opens in a new tab page instead of stacking its splits. Results stay
with their session and open in a read-only JSON split on the right of a wide
screen or below the query on a narrow screen. The companion JSON bind-variable
buffer is unlisted and opens automatically below the query while focus stays
on the query. Selecting another listed AQL query buffer automatically switches
the companion split to that session's variables. The commands below and their
normal-mode mappings are available from both buffers and always target the
associated query. Visual-selection mappings remain query-only.
Collection bind variables such as @@collection use a key such as
"@collection".

aql buffers use a bundled ftplugin: 'omnifunc' completes AQL keywords,
ArangoDB 3.12 built-in function names, and collection names of the session
database, and 'commentstring' is "// %s". Bind-variable buffers offer no
completion. Keywords and functions are available immediately; collection
names come from an asynchronous listing cached per connection and database, so
the first completion starts the fetch and returns only keywords and functions,
while later ones include the collections. A failed fetch stays silent and is
retried on a later call. A leading @ or @@ is not part of the completed word.

When Execute, Profile, Explain, or Validate fails with a positioned syntax
error, one ERROR diagnostic (namespace arangodb.nvim.aql, source ArangoDB) is
placed in the query buffer at the server-reported position, in addition to the
notification. The mark is cleared when the next request starts and after a
successful request; it accounts for a visual selection and for leading text
removed by query normalization. These are Neovim diagnostics, unrelated to the
diagnostics request-journal option.

The following commands are local to AQL query and bind-variable buffers:

                                                        *:ArangoAqlExecute*
:ArangoAqlExecute
    Execute the entire query or command range. The query is explained first
    only when its text contains INSERT, UPDATE, REPLACE, REMOVE, or UPSERT as
    a whole word, case-insensitively; a modification plan then requires
    explicit confirmation. Other queries execute directly, without an explain
    request.

                                                       *:ArangoAqlValidate*
:ArangoAqlValidate
    Parse and validate the query without executing it.

                                                        *:ArangoAqlExplain*
:ArangoAqlExplain
    Show the optimized execution plan without executing the query.

                                                        *:ArangoAqlProfile*
:ArangoAqlProfile
    Execute with profile level 2 and include the plan and node statistics.
    Modification queries use the same explain-then-confirm path as Execute.

                                                       *:ArangoAqlBindVars*
:ArangoAqlBindVars
    Open the associated JSON bind-variable buffer. |:write| validates it.

                                                        *:ArangoAqlHistory*
:ArangoAqlHistory
    Search local query history in a snacks.nvim picker and restore an entry
    without executing it. <Enter> restores the selected entry. The picker
    action key (<C-x> by default) opens Restore, Delete entry, and Clear
    history; clearing asks for confirmation. Loading into an attached .aql
    file keeps changes marked as modified and asks before replacing unsaved
    query edits.

                                                        *:ArangoAqlLibrary-local*
:ArangoAqlLibrary
    Browse, load, or delete named queries scoped to the current connection and
    database in a snacks.nvim picker with search and preview, without
    executing them. <Enter> loads the selected query. The picker action key
    (<C-x> by default) opens Load and Delete; deletion asks for confirmation
    and refreshes the list. Loading into an attached .aql file uses the same
    protection for unsaved query edits as :ArangoAqlHistory. The library
    requires snacks.nvim like the history picker.

                                                           *:ArangoAqlSave*
:ArangoAqlSave
    Create or replace a named query with its current bind variables. Saving
    over an existing name in the same connection and database asks for
    confirmation.

                                                         *:ArangoAqlCancel*
:ArangoAqlCancel
    Cancel the local request and close a known server cursor.

                                                   *:ArangoAqlNextPage*
                                                  *:ArangoAqlPrevPage*
Result buffers provide :ArangoAqlNextPage and :ArangoAqlPrevPage. Previous
pages are cached locally and do not trigger another network request. The
aql_keymaps next_page and prev_page keys (default <C-n> and <C-p>) are set
only in the result buffer; the query buffer does not map them.

                                             *:ArangoAqlResultFormat*
:ArangoAqlResultFormat [json|table]
    Switch the current result page between JSON and a Markdown table. With no
    argument, toggle between both formats. Explain and Validate responses
    always use JSON to preserve their structured details.

                                                    *:ArangoAqlExport*
:ArangoAqlExport [path]
    Export the current result page. The .json, .csv, .md, or .markdown
    extension selects the format. With no path, prompt for one. Exports use an
    atomic replacement and require confirmation before overwriting a file.
    Missing parent directories are created automatically.

:ArangoAqlExport! [path]
    Export every page of the cursor. Remaining pages are fetched through the
    normal paging path and appended to the cached pages, so they stay
    navigable and the server cursor is consumed. Rows are exported in order.
    The displayed page and cursor position do not change. The fetch is
    asynchronous, uses the session's single-request guard, and can be
    cancelled with :ArangoAqlCancel; a failed page request reports an error
    and writes no file. Explain and Validate results have no cursor pages, so
    the bang form exports the displayed response like the plain form.

History defaults to stdpath("data")/arangodb.nvim/aql_history.json, is limited
to 100 entries, and is written with user-only permissions. It excludes URLs,
credentials, results, and errors. Query text and bind variables may themselves
be sensitive; disable history or store_bind_vars when appropriate. After
store_bind_vars is disabled, the next history write also removes bind variables
from retained entries.

A corrupt history or library file is renamed to <path>.corrupt-<timestamp>
with a warning before a new file replaces it, so the damaged content is never
silently overwritten.

Named queries default to stdpath("data")/arangodb.nvim/aql_library.json and
also use user-only permissions. They contain query text and bind variables,
which may be sensitive, but never connection URLs or resolved passwords.

AQL EXAMPLE                                         *arangodb.nvim-aql-example*

With the Docker demo seeded, run :ArangoAql demo and enter:

>sql
  FOR user IN @@collection
    FILTER user.active == @active
    SORT user.name
    RETURN { name: user.name, role: user.role }
<

In the companion bind-variable buffer, enter:

>json
  { "@collection": "users", "active": true }
<

Use :write to validate the JSON and :ArangoAqlExecute to execute the query.
The result contains Alice Martin, Ben Taylor, and Chloe Dubois. After a fresh
seed their roles are Engineer, Designer, and Engineer; the GIF first saves
Alice's role as Maintainer. In the result buffer, use
:ArangoAqlResultFormat table or :ArangoAqlExport /tmp/active-users.csv.
:ArangoAqlExport writes the displayed page; :ArangoAqlExport! fetches the
remaining cursor pages first and exports every row in order.

GRAPH EXPLORER                                          *arangodb.nvim-graph*

|:ArangoGraph| lists Gharial named graphs and asks for a start document ID,
for example users/alice. |:ArangoDocumentGraph| starts from the current saved
document. The explorer performs a breadth-first AQL traversal with bounded
depth and result count. It requests one row beyond graph.max_nodes: when more
vertices exist, it renders graph.max_nodes vertices and the header reads
"Limit: N (truncated — raise graph.max_nodes)" to signal the omitted ones.

Graph-buffer actions:

  <CR>      open the selected vertex document
  s         traverse again from the selected vertex
  r         refresh the current neighborhood
  d         choose a depth from 1 through 10
  t         cycle ANY, OUTBOUND, and INBOUND

                                      *:ArangoGraphRefresh* *:ArangoGraphRoot*
                                                          *:ArangoGraphDepth*
The buffer also provides :ArangoGraphRefresh, :ArangoGraphRoot, and
:ArangoGraphDepth. All graph-buffer keys are configurable with graph_keymaps.

PICKER MAPPINGS                                      *arangodb.nvim-mappings*

Collection picker defaults:

  <Enter>   open collection
  <C-x>     actions menu
  <C-b>     database picker, when available

Document picker defaults:

  <Enter>   open document
  <C-o>     open related document
  <C-f>     change filter field
  <C-u>     reset search
  <C-p>     previous page
  <C-n>     next page
  <C-x>     actions menu
  <C-b>     go back

Navigation and the actions menu work in normal and insert mode. Picker write
mappings are unset by default; create, duplicate, rename, delete, truncate, and
drop remain available from <C-x>. Explicit write mappings are normal-mode-only.
Destructive operations request confirmation with the target database and
resource. Renaming, truncating, dropping, or deleting is refused while a
matching ArangoDB buffer has unsaved changes. Dropping a collection also
refuses system collections, names the collection and its document count when
known, defaults to Cancel, closes the collection's unmodified document buffers
like truncation, and refreshes the collections list on success.

In a collection view, the actions menu also offers these entries; neither is
available in related views. Set picker_keymaps.sort or
picker_keymaps.open_aql for a dedicated key.

  Sort by field…   prompt for an attribute path, then Ascending, Descending,
                   or Default order. The sort appears in the title and is kept
                   across paging, |:ArangoBack|, and |:ArangoResume|; changing
                   it resets paging to page 1 with a fresh cursor.
  Open in AQL      open an AQL editor seeded with an equivalent query and its
                   bind variables: the collection through @@collection, the
                   active filter and sort, LIMIT set to the page size.

The collection and document actions menus expose index management. The
collection actions menu also provides Create document for the selected
collection and the JSON editor for mutable collection properties, including
validation schemas. The index selector uses the configured picker action
mapping (<C-x> by default) for creating, inspecting, and deleting indexes.
<Esc> returns from the action menu to the index selector, then from the index
selector to the previous collection or document picker.

LUA API                                                    *arangodb.nvim-api*

>lua
  require("arangodb").setup(opts)
  require("arangodb").browse({ database = "work" })
  require("arangodb").aql({ database = "work", query = "RETURN 1" })
  require("arangodb").aql({ database = "work",
                            query = "FOR user IN @@collection RETURN user",
                            bind_vars = { ["@collection"] = "users" } })
  require("arangodb").aql_attach({ database = "work" })
  require("arangodb").aql_library({ database = "work" })
  require("arangodb").graph({ database = "work", graph = "social",
                               start = "users/alice" })
  require("arangodb").resume()
  require("arangodb").back()
<

aql() pre-fills the editor: query sets the query buffer text and bind_vars
sets the companion JSON buffer. Collection bind variables use an @name key
such as ["@collection"] = "users"; value variables use their plain name.

Modules behind these commands are reachable too:

>lua
  require("arangodb.aql_history").remove(entry)  -- boolean
  require("arangodb.aql_history").clear()        -- count
  require("arangodb.client").browse_query(collection, field, search, sort,
                                          limit)  -- { query, bind_vars }
<

remove() deletes the entry matching the identity add() de-duplicates on and
reports whether it removed anything; clear() deletes every entry and returns
the count. browse_query() builds the query and bind variables of a document
view: sort is a { field, direction } table or nil, limit defaults to 50, and
the collection and filter go through bind parameters. browse_collection()
gains a trailing sort argument, and browse_collection_async() takes it before
its callback.

TROUBLESHOOTING                                *arangodb.nvim-troubleshooting*

No connection: check setup().connections or export NVIM_ARANGO_<NAME>_URL
before starting Neovim. Auto-discovery is disabled by default.

Wrong database: use the configured alias. Unknown names build URLs using the
NVIM_ARANGO_HOST settings. Environment URL connections use the database name
from the URL, not the variable's <NAME>.

Connection refused: check host, port, container status, and network access.
The demo is bound to 127.0.0.1:18529.

Authentication: check username, password provider, and permissions on the
chosen database and collections. Health checks do not test authorization.

HTTPS: install curl and use tls_ca_file for private certificate authorities.

Picker unavailable: enable snacks.nvim's picker and check plugin load order.

Missing field or relation: discovery uses samples and heuristics; check
field_sample_size and max_field_depth or query the field directly with AQL.

Inspect :messages for errors. Before sharing diagnostics, review hostnames and
request paths; the journal omits credentials, headers, and request bodies.

DEVELOPMENT AND LIMITATIONS                        *arangodb.nvim-development*

Developer commands:

>sh
  make test
  make lint
  make docs
<

Remote picker, document, collection, metadata, and graph operations are
asynchronous and cancellable, and document pagination uses ArangoDB cursors.
Local password commands may briefly block while the configured process exits.
Cancelling AQL closes known cursors and stops the local request. Without an
aql.max_runtime value, an already running server query follows server limits.
HTTPS requires curl. Relation detection is heuristic. The graph explorer is a
bounded textual neighborhood rather than a force-directed canvas. Collection
duplication copies the supported creation properties and non-system indexes;
server-specific properties outside that supported set are not copied. Failure
or cancellation after target creation triggers cleanup; cleanup failures are
reported.

Document and metadata buffers are isolated by configured connection, even
when database names and document IDs match. Reopening an editor preserves
unsaved changes. Edits made during a save remain in the buffer and need another
:write; document saves retain the updated server revision for that next write.

ArangoDB permissions are enforced by the server. Reads and graph traversals
need read access to every consulted collection; document and AQL mutations need
write access to affected collections. Collection creation, rename, truncation,
duplication, properties, schemas, and indexes need the corresponding database
or collection administration privileges for the deployment.

The optional integration suite needs a disposable database and performs
destructive collection operations:

>sh
  ARANGODB_TEST_URL=http://127.0.0.1:8529/_system make integration
<
