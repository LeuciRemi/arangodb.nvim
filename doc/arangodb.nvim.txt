INTRODUCTION                                              *arangodb.nvim-intro*

arangodb.nvim provides a picker-based interface for ArangoDB. It can:

- browse databases, collections, and cursor-paginated documents asynchronously
- search sampled document fields
- edit, validate, explain, execute, and profile AQL queries
- edit JSON documents, save with |:write|, and resolve revision conflicts
- create and duplicate draft documents
- create, duplicate, rename, and truncate collections asynchronously
- edit collection properties and schemas, and manage indexes
- duplicate supported collection properties and secondary indexes
- infer direct, nested, and reverse document relations
- persist named AQL queries, attach real .aql files, and export results
- explore bounded neighborhoods in named graphs
- resolve passwords lazily from functions, environment variables, or commands
- connect through HTTP or HTTPS

The interface uses snacks.nvim. HTTP uses a built-in libuv transport, while
HTTPS uses curl.

===============================================================================
REQUIREMENTS                                      *arangodb.nvim-requirements*

- Neovim >= 0.10
- folke/snacks.nvim with its picker enabled (v2.31.0 is tested in CI)
- curl for https:// connections
- an ArangoDB server reachable through its HTTP API (3.12 is tested)

===============================================================================
INSTALLATION                                      *arangodb.nvim-installation*

Example for lazy.nvim:

>lua
  {
    "LeuciRemi/arangodb.nvim",
    dependencies = {
      { "folke/snacks.nvim", opts = { picker = { enabled = true } } },
    },
    opts = {
      connections = {
        local_db = "http://root:password@127.0.0.1:8529/my_database",
      },
      default_database = "local_db",
    },
  }
<

                                                        *arangodb.nvim-options*

connections ~
    Named connection URLs or structured profiles. Profiles accept url, user or
    username, and one of password, password_env, or password_command. Password
    callbacks and commands are evaluated only when the connection is opened.
    password_command_timeout defaults to 10000 milliseconds.

default_database ~
    Preferred connection name. May also be a { name, url } table.

auto_discover ~
    Query /_api/database/user using the NVIM_ARANGO_HOST settings. Disabled by
    default to prevent implicit network requests during completion and health
    checks.

keymaps ~
    Optional global normal-mode mappings for browse, resume, and back. They are
    unset by default.

picker_keymaps ~
    Picker-local mappings. Navigation and the actions menu work in normal and
    insert mode. Write mappings are unset by default and, when configured, are
    normal-mode-only. Any value may be false to disable that mapping.

document_keymaps ~
    Buffer-local mappings for save, delete, duplicate, related, and graph. They
    are unset by default. The corresponding commands are always created.

graph_keymaps ~
    Graph-buffer mappings for opening a vertex, changing the start vertex,
    refreshing, changing depth, and cycling direction. Any value may be false.

aql_keymaps ~
    Buffer-local AQL editor and result mappings. Any value may be false. No
    global AQL mapping is installed.

aql ~
    AQL editor settings. batch_size controls cursor pages, cursor_ttl is in
    seconds, and max_runtime is nil to use the server default. result_split is
    auto, right, or bottom. result_format is json or table. history configures
    private local history and library.path configures named-query storage.

graph ~
    Named-graph traversal defaults. depth is capped at 10 by the explorer,
    max_nodes bounds a result, and direction is ANY, OUTBOUND, or INBOUND.

layout ~
    snacks.nvim picker layout. preset = "auto" uses a side-by-side layout on
    wide screens and a stacked layout on smaller screens. preview controls the
    preview window.

field_sample_size ~
    Documents sampled when discovering filter and reverse-relation fields.

page_size ~
    Documents requested per ArangoDB cursor page.

json_indent ~
    Spaces used to format JSON buffers and previews.

truncate_length ~
    Maximum displayed field length in picker rows.

max_field_depth ~
    Maximum recursion depth for nested field discovery.

aql_batch_size ~
    Cursor batch size used while consuming AQL responses.

cache_ttl ~
    Lifetime in milliseconds for cached collection metadata, sampled fields,
    and figures. Set to 0 to disable caching. Collection previews load
    per-collection figures and database-wide document and approximate-size
    totals in the background.

default_sort ~
    AQL sort expression used by document and relation listings.

show_system_collections ~
    Include system collections in the collection picker.

http_timeout ~
    HTTP request timeout in milliseconds.

tls_verify ~
    Verify HTTPS certificates. Disabling this is not recommended.

tls_ca_file ~
    Optional CA bundle passed to curl with --cacert.

diagnostics ~
    Optional sanitized JSON-lines request journal. enabled activates it, path
    Credentials, headers, and request bodies are never written.

===============================================================================
CONNECTIONS                                          *arangodb.nvim-connections*

Connection URLs have this form:

  http[s]://[user:password@]host[:port]/database

Authentication is optional. Credentials may be percent-encoded. IPv6 hosts
must use brackets, for example:

>lua
  connections = {
    no_auth = "http://127.0.0.1:8529/example",
    encoded = "https://user%40example.com:p%40ssword@db.example.com:8529/example",
    ipv6 = "http://[::1]:8529/example",
  }
<

Structured profiles keep secrets out of URLs:

>lua
  connections = {
    work = {
      url = "https://db.example.com:8529/work",
      username = "reader",
      password_env = "ARANGODB_WORK_PASSWORD",
    },
    vault = {
      url = "https://db.example.com:8529/vault",
      password_command = { "security", "find-generic-password", "-w",
                           "-s", "arangodb-vault" },
    },
    dynamic = {
      url = "http://127.0.0.1:8529/example",
      password = function(context) return load_secret(context.name) end,
    },
  }
<

password_command may also be a shell command string. It must print only the
password to standard output. It defaults to a 10-second timeout, configurable
with password_command_timeout. Resolved secrets are not shown in completion or
health output.

Avoid storing credentials in version-controlled configuration. Every
NVIM_ARANGO_<NAME>_URL environment variable is detected automatically. The
database name is read from the URL.

Server-wide discovery uses these variables when auto_discover is true:

- NVIM_ARANGO_HOST (default 127.0.0.1)
- NVIM_ARANGO_PORT (default 8529)
- NVIM_ARANGO_SCHEME (http, https, ssl, or tls)
- NVIM_ARANGO_USER (default root)
- NVIM_ARANGO_PASSWORD (default root)
- NVIM_ARANGO_SYSTEM_URL

COMMANDS                                              *arangodb.nvim-commands*

                                                        *:ArangoBrowse*
:ArangoBrowse [database]
    Open the database and collection browser. A database argument skips the
    database picker.

                                                        *:ArangoResume*
:ArangoResume
    Re-show the active picker, or start the browser if no picker is active.

                                                         *:ArangoBack*
:ArangoBack
    Return to the previous picker or document route.

                                                          *:ArangoAql*
:ArangoAql [database]
    Open a new AQL editor. A database argument skips database selection.

                                                   *:ArangoAqlAttach*
:ArangoAqlAttach [database]
    Attach AQL commands and the bind-variable companion to the current .aql
    file without converting it to a scratch buffer.

                                                  *:ArangoAqlLibrary*
:ArangoAqlLibrary [database]
    Open an AQL editor and immediately browse named queries for the database.

                                                        *:ArangoGraph*
:ArangoGraph [database]
    Select a named graph and explore a bounded neighborhood.

                                                *:ArangoDocumentSave*
:ArangoDocumentSave
    Save the current document. A draft is inserted on its first save. |:write|
    performs the same action in an ArangoDB document buffer. Existing
    documents use _rev to detect concurrent changes and offer reload, compare,
    or explicit force-overwrite actions on conflict.

                                            *:ArangoDocumentDuplicate*
:ArangoDocumentDuplicate
    Open a copy of the current document as a draft with a fresh key.

                                              *:ArangoDocumentDelete*
:ArangoDocumentDelete
    Delete the current document after confirmation, or discard a draft.

                                             *:ArangoDocumentRelated*
:ArangoDocumentRelated
    Pick a direct, nested, or inferred reverse relation from the document.

                                         *:ArangoDocumentGraph*
:ArangoDocumentGraph
    Select a named graph and use the current document as its start vertex.

AQL EDITOR                                                *arangodb.nvim-aql*

Every |:ArangoAql| call creates a separate, listed query buffer with the aql
filetype. If the current tab page already contains an AQL session, the next
session opens in a new tab page instead of stacking its splits. Results stay
with their session and open in a read-only JSON split on the right of a wide
screen or below the query on a narrow screen. The companion JSON bind-variable
buffer is unlisted and opens automatically below the query while focus stays
on the query. Selecting another listed AQL query buffer automatically switches
the companion split to that session's variables. The commands below and their
normal-mode mappings are available from both buffers and always target the
associated query. Visual-selection mappings remain query-only.
Collection bind variables such as @@collection use a key such as
"@collection".

The following commands are local to AQL query buffers:

                                                        *:ArangoAqlExecute*
:ArangoAqlExecute
    Explain and execute the entire query or command range. A modification plan
    requires explicit confirmation before execution.

                                                       *:ArangoAqlValidate*
:ArangoAqlValidate
    Parse and validate the query without executing it.

                                                        *:ArangoAqlExplain*
:ArangoAqlExplain
    Show the optimized execution plan without executing the query.

                                                        *:ArangoAqlProfile*
:ArangoAqlProfile
    Execute with profile level 2 and include the plan and node statistics.
    Modification queries require the same confirmation as Execute.

                                                       *:ArangoAqlBindVars*
:ArangoAqlBindVars
    Open the associated JSON bind-variable buffer. |:write| validates it.

                                                        *:ArangoAqlHistory*
:ArangoAqlHistory
    Search local query history with snacks.nvim and restore an entry without
    executing it.

                                                        *:ArangoAqlLibrary-local*
:ArangoAqlLibrary
    Browse, load, or delete named queries scoped to the current connection and
    database without executing them.

                                                           *:ArangoAqlSave*
:ArangoAqlSave
    Create or replace a named query with its current bind variables.

                                                         *:ArangoAqlCancel*
:ArangoAqlCancel
    Cancel the local request and close a known server cursor.

                                                   *:ArangoAqlNextPage*
                                                  *:ArangoAqlPrevPage*
Result buffers provide :ArangoAqlNextPage and :ArangoAqlPrevPage. Previous
pages are cached locally and do not trigger another network request.

                                             *:ArangoAqlResultFormat*
:ArangoAqlResultFormat [json|table]
    Switch the current result page between JSON and a Markdown table. With no
    argument, toggle between both formats.

                                                    *:ArangoAqlExport*
:ArangoAqlExport [path]
    Export the current result page. The .json, .csv, .md, or .markdown
    extension selects the format. With no path, prompt for one. Exports use an
    atomic replacement and require confirmation before overwriting a file.

History defaults to stdpath("data")/arangodb.nvim/aql_history.json, is limited
to 100 entries, and is written with user-only permissions. It excludes URLs,
credentials, results, and errors. Query text and bind variables may themselves
be sensitive; disable history or store_bind_vars when appropriate. After
store_bind_vars is disabled, the next history write also removes bind variables
from retained entries.

Named queries default to stdpath("data")/arangodb.nvim/aql_library.json and
also use user-only permissions. They contain query text and bind variables,
which may be sensitive, but never connection URLs or resolved passwords.

GRAPH EXPLORER                                          *arangodb.nvim-graph*

|:ArangoGraph| lists Gharial named graphs and asks for a start document ID,
for example users/alice. |:ArangoDocumentGraph| starts from the current saved
document. The explorer performs a breadth-first AQL traversal with bounded
depth and result count.

Graph-buffer actions:

  <CR>      open the selected vertex document
  s         traverse again from the selected vertex
  r         refresh the current neighborhood
  d         choose a depth from 1 through 10
  t         cycle ANY, OUTBOUND, and INBOUND

                                      *:ArangoGraphRefresh* *:ArangoGraphRoot*
                                                          *:ArangoGraphDepth*
The buffer also provides :ArangoGraphRefresh, :ArangoGraphRoot, and
:ArangoGraphDepth. All graph-buffer keys are configurable with graph_keymaps.

PICKER MAPPINGS                                      *arangodb.nvim-mappings*

Collection picker defaults:

  <Enter>   open collection
  <C-x>     actions menu
  <C-b>     database picker, when available

Document picker defaults:

  <Enter>   open document
  <C-o>     open related document
  <C-f>     change filter field
  <C-u>     reset search
  <C-p>     previous page
  <C-n>     next page
  <C-x>     actions menu
  <C-b>     go back

Navigation and the actions menu work in normal and insert mode. Picker write
mappings are unset by default; create, duplicate, rename, delete, and truncate
remain available from <C-x>. Explicit write mappings are normal-mode-only.
Destructive operations request confirmation with the target database and
resource. Renaming, truncating, or deleting is refused while a matching
ArangoDB buffer has unsaved changes.

The collection and document actions menus expose index management. The
collection actions menu also provides the JSON editor for mutable collection
properties, including validation schemas. The index selector uses the
configured picker action mapping (<C-x> by default) for creating, inspecting,
and deleting indexes. <Esc> returns from the action menu to the index selector,
then from the index selector to the previous collection or document picker.

LUA API                                                    *arangodb.nvim-api*

>lua
  require("arangodb").setup(opts)
  require("arangodb").browse({ database = "work" })
  require("arangodb").aql({ database = "work", query = "RETURN 1" })
  require("arangodb").aql_attach({ database = "work" })
  require("arangodb").aql_library({ database = "work" })
  require("arangodb").graph({ database = "work", graph = "social",
                               start = "users/alice" })
  require("arangodb").resume()
  require("arangodb").back()
<

HEALTH CHECK                                            *arangodb.nvim-health*

Run:

>vim
  :checkhealth arangodb
<

The health check reports Neovim compatibility, HTTP and HTTPS transports, TLS
settings, snacks.nvim availability, and database candidates. It never prints
passwords.

DEVELOPMENT AND LIMITATIONS                        *arangodb.nvim-development*

Developer commands:

>sh
  make test
  make lint
  make docs
<

Remote picker, document, collection, metadata, and graph operations are
asynchronous and cancellable, and document pagination uses ArangoDB cursors.
Local password commands may briefly block while the configured process exits.
Cancelling AQL closes known cursors and stops the local request. Without an
aql.max_runtime value, an already running server query follows server limits.
HTTPS requires curl. Relation detection is heuristic. The graph explorer is a
bounded textual neighborhood rather than a force-directed canvas. Collection
duplication copies the supported creation properties and non-system indexes;
server-specific properties outside that supported set are not copied. Failure
or cancellation after target creation triggers cleanup; cleanup failures are
reported.

ArangoDB permissions are enforced by the server. Reads and graph traversals
need read access to every consulted collection; document and AQL mutations need
write access to affected collections. Collection creation, rename, truncation,
duplication, properties, schemas, and indexes need the corresponding database
or collection administration privileges for the deployment.

The optional integration suite needs a disposable database and performs
destructive collection operations:

>sh
  ARANGODB_TEST_URL=http://127.0.0.1:8529/_system make integration
<
