INTRODUCTION                                              *arangodb.nvim-intro*

arangodb.nvim provides a picker-based interface for ArangoDB. It can:

- browse databases, collections, and cursor-paginated documents asynchronously
- search sampled document fields
- edit JSON documents, save with |:write|, and resolve revision conflicts
- create and duplicate draft documents
- create, duplicate, rename, and truncate collections
- infer direct, nested, and reverse document relations
- connect through HTTP or HTTPS

The interface uses snacks.nvim. HTTP uses a built-in libuv transport, while
HTTPS uses curl.

===============================================================================
REQUIREMENTS                                      *arangodb.nvim-requirements*

- Neovim >= 0.10
- folke/snacks.nvim with its picker enabled (v2.31.0 is tested in CI)
- curl for https:// connections
- an ArangoDB server reachable through its HTTP API (3.12 is tested)

===============================================================================
INSTALLATION                                      *arangodb.nvim-installation*

Example for lazy.nvim:

>lua
  {
    "LeuciRemi/arangodb.nvim",
    dependencies = {
      { "folke/snacks.nvim", opts = { picker = { enabled = true } } },
    },
    opts = {
      connections = {
        local_db = "http://root:password@127.0.0.1:8529/my_database",
      },
      default_database = "local_db",
    },
  }
<

CONFIGURATION          *arangodb.nvim-configuration* *arangodb.nvim-setup*

Call setup() once after installing the plugin:

>lua
  require("arangodb").setup({
    connections = nil,
    default_database = nil,
    auto_discover = false,

    keymaps = {
      browse = nil,
      resume = nil,
      back = nil,
    },
    picker_keymaps = {
      execute = "<C-x>",
      create = "<C-a>",
      create_collection = "<C-n>",
      duplicate_collection = "<C-d>",
      next_page = "<C-n>",
      prev_page = "<C-p>",
      back = "<C-b>",
      change_field = "<C-f>",
      reset = "<C-u>",
      related = "<C-o>",
      delete = "<C-d>",
      duplicate = "<C-y>",
      truncate = "<C-t>",
      rename = "<C-r>",
    },
    document_keymaps = {
      save = nil,
      delete = nil,
      duplicate = nil,
      related = nil,
    },

    layout = { preset = "auto", preview = true },
    field_sample_size = 200,
    page_size = 50,
    json_indent = 2,
    truncate_length = 120,
    max_field_depth = 4,
    aql_batch_size = 1000,
    cache_ttl = 5000,
    default_sort = "doc._key ASC",
    show_system_collections = false,
    http_timeout = 30000,
    tls_verify = true,
    tls_ca_file = nil,
    diagnostics = {
      enabled = false,
      path = nil,
      max_size = 1048576,
    },
  })
<

                                                        *arangodb.nvim-options*

connections ~
    Named connection URLs. Accepts { name = url } or a list of
    { name = "...", url = "..." } entries.

default_database ~
    Preferred connection name. May also be a { name, url } table.

auto_discover ~
    Query /_api/database/user using the NVIM_ARANGO_HOST settings. Disabled by
    default to prevent implicit network requests during completion and health
    checks.

keymaps ~
    Optional global normal-mode mappings for browse, resume, and back. They are
    unset by default.

picker_keymaps ~
    Picker-local mappings. Any value may be false to disable that mapping.

document_keymaps ~
    Buffer-local mappings for save, delete, duplicate, and related. They are
    unset by default. The corresponding commands are always created.

layout ~
    snacks.nvim picker layout. preset = "auto" uses a side-by-side layout on
    wide screens and a stacked layout on smaller screens. preview controls the
    preview window.

field_sample_size ~
    Documents sampled when discovering filter and reverse-relation fields.

page_size ~
    Documents requested per ArangoDB cursor page.

json_indent ~
    Spaces used to format JSON buffers and previews.

truncate_length ~
    Maximum displayed field length in picker rows.

max_field_depth ~
    Maximum recursion depth for nested field discovery.

aql_batch_size ~
    Cursor batch size used while consuming AQL responses.

cache_ttl ~
    Lifetime in milliseconds for cached collection metadata, sampled fields,
    and figures. Set to 0 to disable caching.

default_sort ~
    AQL sort expression used by document and relation listings.

show_system_collections ~
    Include system collections in the collection picker.

http_timeout ~
    HTTP request timeout in milliseconds.

tls_verify ~
    Verify HTTPS certificates. Disabling this is not recommended.

tls_ca_file ~
    Optional CA bundle passed to curl with --cacert.

diagnostics ~
    Optional sanitized JSON-lines request journal. enabled activates it, path
    overrides stdpath("log")/arangodb.nvim.log, and max_size rotates the file.
    Credentials, headers, and request bodies are never written.

===============================================================================
CONNECTIONS                                          *arangodb.nvim-connections*

Connection URLs have this form:

  http[s]://[user:password@]host[:port]/database

Authentication is optional. Credentials may be percent-encoded. IPv6 hosts
must use brackets, for example:

>lua
  connections = {
    no_auth = "http://127.0.0.1:8529/example",
    encoded = "https://user%40example.com:p%40ssword@db.example.com:8529/example",
    ipv6 = "http://[::1]:8529/example",
  }
<

Avoid storing credentials in version-controlled configuration. Every
NVIM_ARANGO_<NAME>_URL environment variable is detected automatically. The
database name is read from the URL.

Server-wide discovery uses these variables when auto_discover is true:

- NVIM_ARANGO_HOST (default 127.0.0.1)
- NVIM_ARANGO_PORT (default 8529)
- NVIM_ARANGO_SCHEME (http, https, ssl, or tls)
- NVIM_ARANGO_USER (default root)
- NVIM_ARANGO_PASSWORD (default root)
- NVIM_ARANGO_SYSTEM_URL

COMMANDS                                              *arangodb.nvim-commands*

                                                        *:ArangoBrowse*
:ArangoBrowse [database]
    Open the database and collection browser. A database argument skips the
    database picker.

                                                        *:ArangoResume*
:ArangoResume
    Re-show the active picker, or start the browser if no picker is active.

                                                         *:ArangoBack*
:ArangoBack
    Return to the previous picker or document route.

                                                *:ArangoDocumentSave*
:ArangoDocumentSave
    Save the current document. A draft is inserted on its first save. |:write|
    performs the same action in an ArangoDB document buffer. Existing
    documents use _rev to detect concurrent changes and offer reload, compare,
    or explicit force-overwrite actions on conflict.

                                            *:ArangoDocumentDuplicate*
:ArangoDocumentDuplicate
    Open a copy of the current document as a draft with a fresh key.

                                              *:ArangoDocumentDelete*
:ArangoDocumentDelete
    Delete the current document after confirmation, or discard a draft.

                                             *:ArangoDocumentRelated*
:ArangoDocumentRelated
    Pick a direct, nested, or inferred reverse relation from the document.

===============================================================================
PICKER MAPPINGS                                      *arangodb.nvim-mappings*

Collection picker defaults:

  <Enter>   open collection
  <C-a>     create draft document
  <C-n>     create collection
  <C-d>     duplicate collection
  <C-r>     rename collection
  <C-t>     truncate collection
  <C-x>     actions menu
  <C-b>     database picker, when available

Document picker defaults:

  <Enter>   open document
  <C-a>     create draft document
  <C-y>     duplicate document as a draft
  <C-d>     delete document
  <C-o>     open related document
  <C-f>     change filter field
  <C-u>     reset search
  <C-p>     previous page
  <C-n>     next page
  <C-t>     truncate collection
  <C-x>     actions menu
  <C-b>     go back

Destructive operations request confirmation. Renaming or truncating is refused
while a matching ArangoDB buffer has unsaved changes.

LUA API                                                    *arangodb.nvim-api*

>lua
  require("arangodb").setup(opts)
  require("arangodb").browse({ database = "work" })
  require("arangodb").resume()

===============================================================================
HEALTH CHECK                                            *arangodb.nvim-health*

Run:

>vim
  :checkhealth arangodb
<

The health check reports Neovim compatibility, HTTP and HTTPS transports, TLS
settings, snacks.nvim availability, and database candidates. It never prints
passwords.

DEVELOPMENT AND LIMITATIONS                        *arangodb.nvim-development*

Developer commands:

>sh
  make test
  make lint
  make docs
<

Picker reads are asynchronous and cancellable, and document pagination uses
ArangoDB cursors. Explicit mutation commands wait for their server response.
HTTPS requires curl. Relation detection is heuristic. Collection duplication
copies documents and collection type, but not indexes, schemas, computed values,
or other collection properties.

The optional integration suite needs a disposable database and performs
destructive collection operations:

>sh
  ARANGODB_TEST_URL=http://127.0.0.1:8529/_system make integration
<
